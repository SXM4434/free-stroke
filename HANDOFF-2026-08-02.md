## 8 · WHAT O5 ACTUALLY NEEDS — measured, so the next lane does not re-derive it

`hero-motion.ts` says O5 needs *"a per-letter transform index as a vertex attribute and an
array of inverses in both shaders."* Having read the path, there is a simpler equivalent:

- Every stroke ALREADY renders inside its own `<group>` (`viewport-3d.tsx` :4061), and the
  main tube mesh carries **no local transform** — so geometry can move per letter today.
- The single blocker is that all meshes share ONE `liveMaterial`, and the carve, joint-break
  and pen-tip passes each map a fragment to field space with **one** uniform,
  `uFsBreakInv = inv(flattenGroup.matrixWorld)`. Put a transform on a letter group and that
  inverse returns the MOVED position instead of the field position.
- The shader math is `fsQ = inv(flattenWorld) · modelMatrix · transformed`. `modelMatrix` is
  already per-draw-call and is what makes the rod CAPS correct (they carry `position=`), so
  it cannot be replaced with a baked attribute without breaking caps.
- **Therefore: per-letter MATERIAL INSTANCES, each with its own `uFsBreakInv`.** No vertex
  attribute, no uniform arrays, caps keep working. The cost is N material instances and N
  uniform writes per frame — trivial at eleven letters. The entanglement is that
  `liveMaterial` is referenced in ~20 places and becomes an array.

O3b needs the same enabling refactor for its per-stroke `flat`, since `ink` is applied by
mutating that one shared material (`viewport-3d.tsx` :3474). **Do the material-instance
refactor once; it unlocks both.**

## ⚠️ HALF-BUILT AND FLAGGED: `applyLetterMotion` (O5's mechanism)

`components/viewport-3d.tsx` carries a NEW, INERT vertex pass for per-letter motion. It is
green (`tsc` 6, drawin-parity ALL PASS) and it changes nothing today, but it is scaffolding
and not a feature: **the attribute is never stamped, the uniforms are never written, and
there is no film that drives it.** Either finish it or delete it — do not leave it as is.

**Its mechanism is worth keeping, because the blocker everyone assumed is not real.**
`hero-motion.ts` said O5 needs *"a per-letter transform index as a vertex attribute and an
array of inverses in both shaders."* It does not need the inverses. `applyJointBreak`
captures the field position in the VERTEX shader BEFORE `<project_vertex>`:

    vFsBreakWorld = (modelMatrix * vec4(transformed, 1.0)).xyz;
    #include <project_vertex>

So a rotation applied to `transformed` AFTER that line and BEFORE the projection moves the
letter while the varying still carries its ORIGINAL position — the carve, break and tip
