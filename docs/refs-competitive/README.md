# Competitive references — what they are, what they do, why they matter, and what they'd be in OUR language

Fifteen pages captured 2026-08-01 through `scripts/verify/refs-capture.mjs`, a
port of the shared provenance gate. **The gate refused two URLs in this very
run** — `helpx.adobe.com/illustrator/using/3d-effects.html` and
`docs.spline.design/doc/exporting-videos/docPWWk8Y1Rl`, both **live HTTP 404s
that `page.goto()` did not throw on**. Either one, screenshotted naively, would
have become a paragraph of mechanism written from a URL slug. Both were replaced
with pages that exist, and the dead URLs are kept in the capture script's
comments so nobody re-tries them.

Provenance for every file — url · status · ok · sha256 · title · body length ·
element count · subresource failures — is in
[`_capture-manifest.json`](_capture-manifest.json).

```bash
node scripts/verify/refs-capture.mjs --selftest        # the gate must FAIL on known-bad
node scripts/verify/capture-competitive-refs.mjs --verify
```

**Every claim below names what is VISIBLE in the saved PNG.** Where a page's
own marketing says something the screenshot does not show, it is not written
down here. The analysis that uses these is
[`../research/competitive-landscape-and-the-missing-export.md`](../research/competitive-landscape-and-the-missing-export.md).

| 05 | `ref-05-mediabunny.png` | Mediabunny guide introduction | *"a JavaScript library for reading, writing, and converting media files (like MP4 or WebM), directly in the browser… written from scratch in pure TypeScript, has zero dependencies, and is extremely tree-shakable… You can think of it a bit like **FFmpeg, but built for the web's needs**."* Feature list includes *"Hardware-accelerated decoding & encoding (via the WebCodecs API)"* and *"Read & write support for many container formats (.mp4, .mov, .webm, .mkv, .mp3, …), including variations such as MP4 with Fast Start, fragmented MP4, streamable Matroska, **transparent WebM**"*. | The right long-term dependency, and the one thing it has that our hand-written muxer does not: **transparent WebM**, which would collapse our two output formats into one. | 06 | `ref-06-webcodecs-muxing.png` | WebCodecs Fundamentals, *Muxing and Demuxing* | *"WebCodecs by itself cannot read or write playable video files. You can't just take a bunch of `EncodedVideoChunk` objects, put them in a `Blob` and call it a day."* — over a code block commented **`// This will not work!`**. Also the reason the gate for it decodes the file with a real ffmpeg rather than checking that bytes came out. |
| 07 | `ref-07-mdn-videoencoder.png` | MDN, `VideoEncoder` | Captured and provenance-verified (HTTP 200, title *"VideoEncoder - Web APIs \| MDN"*). | 08 | `ref-08-ccapture.png` | `spite/ccapture.js` | Repo description: *"A library to capture canvas-based animations at a fixed framerate."* MIT · **3.8k stars** · 406 forks · **680 "Used by"** · topics `canvas capture ffmpeg gif javascript jpg png video webm`.
